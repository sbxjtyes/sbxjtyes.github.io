它是怎么跑起来的（一句话）

别人发信到 *@sbxjtyes.me → Cloudflare 代收 → Worker 存进数据库 → 你的网页收件箱显示

⚠️ 开始前先看两点

1. 有个等待。第 2 步改完 DNS 后，要等 Cloudflare 把你的域名激活（几分钟到几小时，最长 1–2 天）。等待期间你可以先做 第 4 步（命令行部署），它不依赖域名生效，能省时间。

2. 有些操作只能你本人做。注册账号、改 Namecheap 的 nameserver、命令行里点授权——这些涉及你的账号密码，我没法替你点。代码和命令都给你了，卡住了把报错发我。

1

注册 Cloudflare，把 sbxjtyes.me 加进去

在网页里操作 · dash.cloudflare.com
  1. 打开 dash.cloudflare.com/sign-up，用邮箱 + 密码注册，然后去邮箱点验证链接、登录。
  2. 登录后，点右上角 + Add → Connect a domain（首页也有 “Add a site” 大按钮）。
  3. 输入 sbxjtyes.me，点 Continue。
  4. 套餐选最下面的 Free（$0），Continue。
  5. Cloudflare 会自动扫描你现有的 DNS 记录。核对下面这几条在不在（这是你现在的 GitHub Pages 网站，保住它网站才不会挂）。缺了就点 “Add record” 手动补上：
类型名称内容代理状态
A@185.199.108.153DNS only（灰云）
A@185.199.109.153DNS only（灰云）
A@185.199.110.153DNS only（灰云）
A@185.199.111.153DNS only（灰云）
CNAMEwwwsbxjtyes.meDNS only（灰云）

点每条记录右边的橙色云朵图标可切成灰色（DNS only），GitHub Pages 用灰云最稳。

✓ 这步成功的标志

你进入到 “Change your nameservers（更换域名服务器）” 页面，看到 Cloudflare 分给你的两个地址，形如 xxx.ns.cloudflare.com。下一步要用它俩，先别关这个页面。

2

在 Namecheap 把 nameserver 改成 Cloudflare 的

在网页里操作 · namecheap.com
  1. 登录 namecheap.com → 右上账户 → Domain List。
  2. 找到 sbxjtyes.me，点右边的 Manage。
  3. 往下找到 NAMESERVERS 那一栏，把下拉框从 “Namecheap BasicDNS” 改成 Custom DNS。
  4. 出现两个输入框，分别填入第 1 步 Cloudflare 给你的两个地址（一行一个）。
  5. 点旁边的绿色对勾 ✓ 保存。
✕ 常见错误

把两个地址填反没关系，但别填错字母、别多空格；不要保留 Namecheap 原来的那两条（要整个替换）。

✓ 这步成功的标志

回到 Cloudflare，那个域名的状态会从 Pending（待处理） 变成 Active（已激活）。这需要时间——几分钟到几小时，最长 1–2 天。激活后 Cloudflare 会发邮件通知你。

👉 别干等：现在就可以往下做 第 4 步（命令行部署不需要域名生效）。等激活了再回来做第 3、5 步。

3

开启 Email Routing（让 Cloudflare 替你收信）

在网页里操作 · 需要域名已 Active
  1. Cloudflare 仪表盘里点开 sbxjtyes.me。
  2. 左侧菜单找到 Email → Email Routing。
  3. 点 Get started / Enable。它会提示自动添加收信需要的 MX 记录 + SPF（TXT），一路确认即可。
  4. （可选）“Destination addresses” 里可以加你的 Gmail 并验证——只有当你想把某些邮件转发到 Gmail 时才需要。做临时邮箱走 Worker 的话，这步可跳过。
⚠️ 注意

开启后，你原来 Namecheap 自带的邮件转发会失效（本来就是要用 Cloudflare 替换它）。这对做临时邮箱没影响。

✓ 这步成功的标志

Email Routing 页面顶部显示 Enabled；在 DNS 记录里能看到几条指向 route1/2/3.mx.cloudflare.net 的 MX 记录。

4

命令行：登录、建数据库、部署

在 PowerShell 里操作 · 可在等域名生效时先做

4.0 打开 PowerShell，进到项目的 cf-worker 目录：

PowerShell
cd "C:\Users\YS\Desktop\A\running\注册机\TemGmailRegister\cf-worker"

4.1 登录 Cloudflare（会弹出浏览器，点 Allow 授权，然后回到终端）：

PowerShell
npx wrangler login

4.2 创建 D1 数据库。运行后，复制输出里的那行 database_id = "..."：

PowerShell
npx wrangler d1 create tempmail

4.3 打开 cf-worker/wrangler.toml，把里面 PASTE_DATABASE_ID_HERE 换成上一步那个 id，保存。

🙋 不想自己改？

把 wrangler d1 create 输出的那行 id 发给我，我直接帮你填进 wrangler.toml。

4.4 建表（在云端数据库里创建存邮件的表）：

PowerShell
npm run db:init

4.5 部署。第一次会让你起一个 *.workers.dev 子域名（随便起，比如 ys-temp），确认即可：

PowerShell
npm run deploy
✕ 两个最容易踩的坑

忘了填 database_id → 部署报 D1 binding 相关错误。回 4.3 填好。

忘了 4.4 建表 → 界面能打开，但一收信/刷新就报 no such table: messages。补跑 npm run db:init。

✓ 这步成功的标志

终端最后显示部署成功，给你一个网址：https://tempmail.你的子域.workers.dev。打开它，能看到临时邮箱界面（这时还收不到信，因为第 5 步的 catch-all 还没设）。

5

把「收到的所有邮件」接到 Worker

在网页里操作 · Email Routing → Routing rules
  1. 回到 Email → Email Routing，点 Routing rules 标签。
  2. 找到 Catch-all address（通配收件） 那一行，点 Edit。
  3. Action（动作）选 Send to a Worker，下拉里选你刚部署的 tempmail。
  4. 确保 Catch-all 的开关是启用（Enabled），Save 保存。
✓ 这步成功的标志

Catch-all 那行显示 Active，动作是 Send to Worker: tempmail。至此，任何发往 任意名字@sbxjtyes.me 的邮件都会进你的收件箱。

6

发一封信，验证成功

用任意邮箱测试
  1. 打开你的 *.workers.dev 网址，记下页面顶部那个 xxxx@sbxjtyes.me 地址（也可点 “换一个”）。
  2. 用你的 Gmail 给这个地址发一封信（标题正文随便写）。
  3. 回到网页等几秒（每 5 秒自动刷新），邮件就会出现在收件箱，点开能看正文。外部图片默认拦截，可点 “显示图片”。
✕ 没收到？按顺序排查

1) 域名在 Cloudflare 是 Active 了吗？（第 2 步）

2) Email Routing 是 Enabled 吗？（第 3 步）

3) Catch-all 指到 tempmail 了吗？（第 5 步）

4) 看 Worker 实时日志：在 cf-worker 里跑下面这条，然后再发一封信，看有没有事件或报错：

PowerShell
npm run tail

5) 确认你发信的地址域名拼写没错（sbxjtyes.me）。

🎉 成功了

收到信、能点开看正文，就全部搞定了。以后随时打开那个网址，用 @sbxjtyes.me 的地址去各处注册即可。

＋

之后可选的增强

不做也能正常用
  • 加登录保护（推荐）：这个网页现在是公开的，任何知道网址的人都能查 @sbxjtyes.me 的收件箱。想私有，可用 Cloudflare Zero Trust → Access（免费）在前面加一层登录。需要的话我帮你配。
  • 换个短域名入口：给 Worker 绑定 mail.sbxjtyes.me，就不用记 workers.dev 那串。不影响你 apex 上的 GitHub 网站。
  • 调保留时长 / 清理频率：改 wrangler.toml 里的 [vars] 和 [triggers] crons，再 npm run deploy。
  • 保留附件：目前只存正文（text/html），需要下载附件可以再加。
